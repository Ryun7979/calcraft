# 派手さマシマシ改編 指示書

既存のアプリを、highfive_dopa（はちゃめちゃタイプ）と同じ「1操作ごとに気持ちいい、ド派手な演出」のアプリに作り変えるための指示書です。
Claude Code に渡して使います。**仕組みと進め方は highfive_dopa から引き継ぎ、キャラクターとデザインテイストは対象アプリのイメージに合わせて新しく作ります。**

- 参照元: https://github.com/Ryun7979/highfive_dopa（`docs/spec.md`・`LEARNINGS.md`・`docs/learnings/`）
- 【 】の部分は、対象アプリに合わせて埋める（または §2 の質問でユーザーに決めてもらう）

---

## 0. この指示書の使い方

1. 対象アプリのリポジトリに `docs/hade-mashimashi-playbook.md` として置く。
2. Claude Code に「この指示書に沿って改編を進めて」と頼む。
3. Claude Code は §2 の質問から始め、§3 のフェーズ順に進める。フェーズごとに計画を出し、承認を得てから実装する。

**AIへの約束（この指示書を読んだ Claude Code が守ること）**
- 出力・報告・コミットメッセージは日本語。
- 「計画 → 確認 → 実行」。実装の前に「この方針で進めてよいか」を聞く。
- コミット・プッシュはユーザーの指示があるまでしない。
- highfive_dopa のキャラ（ラビッドパ）・デザイン部品（`hx-*`・ネオン×ステッカー×コミック）・ロゴ・画像・曲は**流用しない**。流用してよいのは「仕組み・数値の考え方・コードの構造」だけ。

## 1. ゴールと原則

### 1.1 ゴール
- **1操作ごとに、画面と音で何かが起きる。** 【対象アプリの「1操作」：例 タップ・正解・1問クリア・1歩進む】
- **続けるほど派手になる。** 連続成功（コンボ）→ FEVER → 倍々、と段階的に盛り上がる。
- **気づいたら何回も遊んでいる。** 遊ぶたびに何かが増える（レベル・ガチャ・図鑑・ミッション）。

### 1.2 原則（highfive_dopa で効いたもの）
1. **「聖域」を1つだけ決めて、そこだけは演出より優先する。** highfive_dopa では「出題文字のサイズ（視力の弱い子でも読める）」。それ以外（光の点滅・配色の読みやすさ）は派手さを優先した。対象アプリの聖域は §2 で決め、仕様書の §3 に「変更不可」として書く。
2. **中核ロジックは書き換えず、足し算で拡張する。** 判定・計算・データ構造など、元アプリの核は残す。
3. **演出の数値と、進み方（ごほうび）の数値は分ける。** スコアは倍々でふくらませても、コイン・経験値は別の「ごほうび用スコア」で数えて、進む速さを壊さない。
4. **やさしめにする。** 失敗の罰は軽く（ゲージは一部残す、ミスで減点しない）。むずかしくする方向の調整はしない。
5. **数値は1か所に集める。** しきい値・倍率・時間はすべて `【rules ファイル】` の定数にし、試算で決める。
6. **完全オフライン・外部通信なし・課金なし。** CDN や外部 API、解析タグを足さない。フォントと素材は同梱する。

## 4. 演出カタログ（highfive_dopa の実装と数値）

【 】の「1操作」「成功」「失敗」を対象アプリの出来事に読み替えて移植する。数値は highfive_dopa（低学年向け）の値なので、対象ユーザーに合わせて試算しなおす。

### 4.1 1操作ごとの「ジュース」
- パーティクルがはじける（同時数に上限：ふだん 300、FEVER 中 450）
- 操作した対象（文字・アイコン）のコピーが画面外へ飛んでいく
- 弱い全画面フラッシュ（約0.1秒。強いフラッシュの最中は上書きしない）
- 操作音は、コンボが続くほど音階が上がる（1オクターブでループ）
- ゲージが増えたら「+5」がはね、満タンを超えたら「MAX!!」、ミスで減ったら赤く光って赤白のしまが残って縮む

### 4.2 コンボ（連続成功）の段階

| コンボ | 倍率 | 演出段階 | キャラ |
|---|---|---|---|
| 0–4 | ×1.0 | 通常 | ふつう |
| 5–11 | ×1.2 | パーティクル増量 | ノリノリ |
| 12–24 | ×1.5 | 画面シェイク＋背景加速＋集中線 | さけぶ・オーラ小 |
| 25–49 | ×2.0 | 色反転＋ズームパルス＋フラッシュ | 踊る・オーラ大 |
| 50+ | ×3.0 | 最大演出 | 覚醒 |

- 段階が上がるとキャラが画面中央へ飛び出すカットイン。10コンボごとに上部の帯のカットイン。
- 低学年でも1プレイで段階が上がるよう、しきい値は低めにした。

### 4.3 FEVER（ゲージ制・倍々）
- ゲージ満タン（1操作 +5、成功 +10、100で満タン）で FEVER 突入。FEVER の外でミスしても ゲージは4分の3残る。
- **FEVER は時間ではなくゲージで続く。** 入ると満タン、何もしなければ10秒で空、1操作 +3・成功 +5 で回復、ミス −10、空で終了。
- 続けると段階が上がる：×2 → ×4 → ×8 → ×16（15 / 20 / 25 操作ごと）。段階ごとにゲージの減りが速くなり、花火の間隔・パーティクル量・ふちのネオンの太さが倍々で増える。
- 突入演出（2.4秒・3段）：暗転して虹の放射線が収束 → 帯が開きキャラが左右から突っ込む → 「FEVER!!」を1文字ずつ叩きつけ、花火12連発と紙ふぶき。
- FEVER 中は BGM を専用の曲に切り替える。
- **画面のスコアは倍々でも、コイン・経験値は ×2 までで数える「ごほうび用スコア」で計算する。**

### 4.4 運のボーナス
- 一定確率（10%）で「ゴールデン」（金色に光る対象）が出る。クリアで10秒のボーナスタイム（スコア・コイン ×2）。
- FEVER と重なると「W ボーナス!!」。
- 出た瞬間：フラッシュ・輪・はじけ・ゆれ＋金の帯のお知らせ。**ゴールデンの見た目は色と光だけにし、聖域（サイズなど）には触れない。**

### 4.5 開始のカウントダウン（約3.2秒）
- 「よーい… → 3 → 2 → 1 → GO!!」。数字ごとに色・傾き・花火の数を増やし、キャラが力をためて、GO で飛び上がる。
- タイマー・1問目・プレイ曲は GO の瞬間に始める。カウント中の操作は無視する（ミスにしない）。

### 4.6 失敗したとき
- 「ガシャーン」の効果音、赤フラッシュ、キャラがずっこける。
- コンボは0に戻るが、ゲージは一部残す（やさしめ）。

### 4.7 結果発表
- ランク C / B / A / S / SS / SSS / ∞（∞ はほぼ届かない演出用）。バッジは画像、A 以上でジングル。
- 「あと○点で S ランク！」「自己ベストまであと○点！」を出し、Enter 一発でもう一回。

### 4.8 成長と収集
- **レベル・スキルツリー**：レベルアップごとにスキルポイント。枝は「あそび（モード解放）」「ブースト（有利になる）」「えんしゅつ（演出追加）」。振り直しは無料。聖域に関わる設定はスキルで縛らない。
- **ガチャ**：ゲーム内コインだけ（課金・広告なし）。中身は 衣装／エフェクト／音／背景 の4カテゴリ×6種（初期装備1つ＋ガチャ20種）。排出率 N 60 / R 30 / SR 8 / SSR 2%（画面に表示）、天井20回でSR以上、重複は「かけら」→10個で交換。
- **ガチャ演出**：カプセルが落ちてゆれ、色が 白 → 青 → 金 → にじ と上がる。長さはレア度で変える（N 約2秒〜SSR 約6.5秒）、ときどきフェイント。クリック・Enter で飛ばせる。結果はボタンを押した時点で決めて保存し、見せ方だけ遅らせる。
- **図鑑**：未入手はシルエット、押すと装備してその場で試せる。
- **デイリーミッション**：1日3つ、全部できたらボーナス、連続日数。途切れても罰はなし。
- **休けいお知らせ**：連続プレイ時間が設定値（初期30分）を超えたら、プレイの終わりにキャラが声をかける。オプション画面で誰でも変更可。

### 4.9 【重要】大きなカットインのあいだは進行を止める
- 画面の主要部分を隠すカットイン（段階アップ・FEVER 突入・ボーナス突入など）のあいだは、タイマー・ゲージの減り・次の問題への進行を止める。
- 操作は受け付けてよいが、失敗はミスに数えない。止まるタイマーは1つの仕組み（止められるタイマー）に集約する。
- 隠さない帯（上部の○コンボなど）は止めない。

### 4.10 演出のつよさ
- 「ひかえめ／ふつう／MAX」（初期値は MAX）。ひかえめはフラッシュ・シェイク・色反転・大きなカットインを出さず、パーティクルを減らす。長さと流れは変えない。

## 5. 相棒キャラクター（新しく作る）

**ラビッドパは流用しない。** 対象アプリのイメージに合ったキャラを、§2 の決定どおりに用意する。仕組みだけ次のとおり引き継ぐ。

### 5.1 作り方
1. デザインを受け取る（または Gemini で案を出してユーザーが選ぶ）。元絵は `docs/character/reference.*` に置き、変更不可にする。
2. **SVG で描き直してパーツに分ける**（例：頭・目・口・胴・腕・足・耳やしっぽ など、そのキャラの特徴的な部位）。
3. **「pose → SVG」を返す関数を作る**（`render【キャラ名】(pose)`）。pose の例：表情、各部位の角度と伸び倍率、腕の角度・長さ・しなり、足の伸び（伸びた分だけ体が持ち上がる）、体のつぶれ（体積を保つ）、傾き。
4. **アニメは「時間 t（秒）→ pose」の関数**で書く。数値を変えるだけで動きを直せる。ループさせるものは長さを割り切れる値に揃える。
5. ブラウザで直接開けるデモ `docs/character/preview.html`（JS を埋め込んだ1ファイル）と GIF を作り、ユーザーに見てもらう。
6. React コンポーネント化し、rAF で pose を更新する（React の再描画には乗せない）。

### 5.2 必要な動き（役割の表）

| 動き | 使う場面 | highfive_dopa での例 |
|---|---|---|
| 待機 | ふだん | ゆっくり弾む、耳がゆれる |
| ため | 開始カウントダウン中 | 体をちぢめてぷるぷる |
| カウント | カウントの数字ごと | 踏みこんでこぶしを突き上げる |
| 正解・成功 | 1操作ごと | つぶれて弾み、万歳 |
| さけぶ | コンボ上位段階 | 星目、耳が1.5倍に伸びる |
| FEVER ダンス | FEVER 中 | 左右の足を交互に伸ばして踊る |
| ジャンプ | 大きな成功 | 足が伸びて大ジャンプ |
| ずっこけ | 失敗 | 傾いて片足が跳ね上がる |

- 「手足や耳が伸びる」のように、**そのキャラならではの誇張できる部位**を1つ以上決めて、派手に動かす。
- 配置は画面の端が基本。演出時は中央へ飛び出してよいが、**聖域にはかからない**ようにする。
- 衣装・オーラは SVG の上に重ねるレイヤーにし、ガチャの「衣装」と同じ仕組みにする（カラー違いを衣装にすると安く数を増やせる）。

## 6. デザインテイスト（新しく決める）

**highfive_dopa の見た目（ネオン×ステッカー×コミック、`hx-*` の部品）は流用しない。**

1. §2 の「3語コンセプト」から、色（地の色1・アクセント2〜4）、フォント（見出し1・本文1、同梱できるもの）、形のルール（角丸・傾き・ふちの太さ）を決め、見本画面を1枚作ってユーザーに確認する。
2. 部品を CSS クラスにまとめる：ボタン、タグ、パネル、ステッカー（目立たせる札）、ゲージ、テープ（流れる帯）、バースト（ギザギザの吹き出し）、カットインの大きな文字。色は CSS 変数と Tailwind の色トークンを同じ値にする。
3. ロゴは画像にする（Gemini で作る）。
4. メニュー系の画面は 1280x720 以上でスクロールなしに収める。低い表示領域では、広い仮の画面に描いて縮める。
5. 言葉づかいは対象ユーザーに合わせる（低学年ならひらがな・カタカナ中心）。

## 7. 音

- **BGM は4曲**：タイトル／プレイ／FEVER／リザルト（Gemini で作る）。FEVER は倍速ではなく別の曲に切り替える。
- **ジングル**：FEVER 突入・ボーナス突入・段階アップ・ガチャ SSR・レベルアップ・スキル解放・ランク発表。Gemini の曲から切り出す（頼んでも数秒の曲は返らない）。
- **短い効果音は Web Audio の合成**のまま（操作音・成功・失敗・節目）。
- 音のバランスは1ファイル（`audioManager`）に集める：曲の大きさ（ふつう 0.38、FEVER 0.55）、成功音は大きくして鳴るあいだ曲を下げる（ダッキング）、出口にリミッター。新しい音は同じ包み方で足す。
- 曲の切り替えは「いまの曲以外ぜんぶ止める」形にする。画面を離れたらジングルを止める。タブが裏に回ったら止め、戻ったら再開する。

## 8. 素材制作（Gemini の Web 画面・API 禁止）

- **Google Gemini を Web 画面からブラウザ操作して作る。Gemini API（他社の生成 API も）は使わない。** API キーや `.env` を足さない。
- 手順はスキル（`.claude/skills/gemini-assets/SKILL.md`）にまとめ、採用した素材は `docs/assets.md` の台帳にプロンプト全文と加工内容を記録する。未採用の素材は `_inbox/`（git 管理外）に置く。
- 頼み方のコツ（highfive_dopa で確認済み）
  - **1枚ごとに新しいチャット＋全部入りのプロンプト。** 同じチャットで題材だけ変えると前の絵を引きずる。
  - **透過したい絵は「真っ白な背景＋絵の外側を濃い太い縁で囲む」で頼み、手元で切り抜く。** ロゴ・バッジはこれで1回で通った。文字入りの絵は、文字を1つずつ指定する。
  - **小さな絵をたくさん作るときは 2×2 のシート1枚**で頼み、手元で4つに切る。「お互いに大きく間をあける・ます目の線は描かない」と書く。
  - 背景に「上に文字が乗る」と書くと文字を描かれる。「中央から上は広く空ける」とだけ書く。
  - BGM は「音楽を作ってください。」で始まる短いプロンプト。長い指示は失敗しやすい。ダウンロードは MP3。
  - 上がる感じのジングルがほしいときは「低い音から高い音へ上がりつづけ、下がるフレーズは入れない」と書く。候補は複数作り、ユーザーに聞いてもらう。
  - 入力は入力欄に `insertText` で流しこみ、送信ボタンを押す（キー入力だと半角英数字が抜けることがある）。
  - ダウンロードしたファイルは日時でしぼって取りこむ（古い別のファイルをつかまない）。

## 9. 実装のパターン

- **演出は React の再描画に乗せない。** パーティクルとフラッシュは Canvas に ref で命令、シェイクとズームは `element.animate()`、キャラは rAF で描き直す。操作ごとの state 更新は HUD の数値だけ。
- レイヤー：背景 → 主要エリア（聖域） → 演出 Canvas → キャラ → UI。
- 数値は `【rules ファイル】` に、スキルの効果は `getMods(skills)` が返す1つの型に、装備は `getEquipped(category)` に集約する。アイテムを足すときは定義表に1行足すだけにする。
- 保存は localStorage の1キー。書き換えは `mutateSave(fn)` に集約し、足りない項目は読み込み時に初期値で埋める。プレイ後の書き込み（コイン → デイリー → 経験値）は1回にまとめる。
- 乱数・日付・時刻は引数で渡せる純粋な関数にする（ガチャ・デイリー・休けい判定）。試算と確認が楽になる。
- 時間で進む処理は「止められるタイマー」に乗せる（§4.9）。
- Tailwind のクラス名は完全な文字列で書く（組み立て不可）。`tailwind.config.js` を変えたら開発サーバーを再起動する。

## 10. 検証のしかた

- **自動プレイスクリプト**：ブラウザの JS から正しい操作を送り続け、1プレイを数秒で回す。その間に聖域の実測値（例：文字の `fontSize`、エリアの高さ）を記録し、最小値で合否を判定する。画面幅（1920 / 1280 / 1024 / 768 / 横向きスマホ）と設定の組み合わせで回す。
- **数値の試算**：純粋な関数を束ねて node で実行し、腕前6段階（0.5操作/秒・ミス20% 〜 8操作/秒・ミス1%）× 400回で分布を見る。ランクのしきい値・ごほうび・天井はこれで決め、「何回遊ぶと全部そろうか」の表を仕様書に残す。
- **文字の重なり**：`Range.getBoundingClientRect()` を総当たりで比べて、5px 以上重なる組を列挙する。
- **途中の絵を撮る**：`animation-play-state: paused`＋負の `animation-delay`、または `setTimeout` の待ち時間をその演出だけ引きのばして止める。
- **音**：OfflineAudioContext で各音の大きさ（50ms の RMS の最大）を測って比べる。耳での確認はユーザーに頼み、未確認のものは `LEARNINGS.md` の Open Questions に残す。
- 完了の判定は `npm run build`（型チェック込み）と、上の実測値。報告には実行したコマンドと出力を添える。

## 11. よくある落とし穴（highfive_dopa で実際に踏んだもの）

- 打鍵ごとの強いフラッシュが重なって、主要部分が白くかすんだ → 弱く短く、強いものを弱いもので上書きしない。
- 画面を隠すカットイン中も時間が進み、損をした → §4.9 のとおり止める。
- 叫び文字を何色も混ぜたら「素人っぽい」と言われた → 1つの色あいの濃淡＋1方向の影だけにする。
- 自作の CSS クラスに `display` を書いて、Tailwind の `flex` を打ち消し、文字が重なった。
- 傾けた部品に transform のアニメを付けて傾きが消えた → 外側に1枚かぶせる。
- 確認に使ったブラウザのタブを開いたままにして、タイトル曲が鳴りつづけた → 確認が終わったらタブを閉じる。
- 開発サーバーでページを開いたまま音のファイルを書き換え、曲が二重に鳴った → 書き換えたらページを開きなおす。
- `public/` のファイルに長期キャッシュを付けると、差し替えても古いものが残る → ハッシュ付きのファイルだけ長期キャッシュにする。
- 「OFFLINE」と名前にあっても外部通信していた → `grep -rn "https://"` とビルド後の通信で確かめる。
