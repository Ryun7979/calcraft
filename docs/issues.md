## 1. メニューから始めてもレベル自動調整が走る

- 場所: `src/components/MenuScreen.tsx`（「あそぶ！」ボタン）、`src/hooks/useGame.ts` の `startGame`
- 原因: `onClick={startGame}` なので、クリックイベントが `startGame(isRetry)` の `isRetry` に渡り、真として扱われる。
- 起きること: 1回遊んで（回答が `TOTAL_QUESTIONS` 件たまった状態で）「タイトル」に戻り、「あそぶ！」を押すと、
  リトライ扱いになってレベルの自動調整（連続満点・連続低得点のカウント）が動く。メニューで選んだレベルが勝手に変わることがある。
  また本来メニュー開始時に行う「連続カウントと `hasLeveledUp` のリセット」も行われない。
- 直し方の案: `onClick={() => startGame(false)}` にする。
- メモ: マシマシモードのメニュー（`HypeMenuScreen`）は `startGame(false)` を明示して呼んでいるので、この不具合は出ない。ひかえめモードの画面は変更しない方針のため未修正。

## 2. ひきざん Lv3 でくり下がりのある問題が出る

- 場所: `src/lib/gameLogic.ts` の `sub` / `grade === 3`
- 原因: `num1 = random(11, 99)` で一の位が 0（20, 30, …）になると、`num2 = random(1, num1 % 10 || 1)` が 1 になり、`20 − 1` のような「くり下がりあり」の問題になる。
- 直し方の案: `num1` の一の位が 1〜9 になるように選ぶ（例: 十の位 1〜9、一の位 1〜9 を別々に選ぶ）。

## 3. わりざん Lv1〜3 の出題が同じ

- 場所: `src/lib/gameLogic.ts` の `div` / `grade <= 3`、`src/constants/difficulty.ts`
- 内容: Lv1〜3 はすべて「九九のぎゃく（あまりなし）」で、生成処理も同じ。レベルを上げても難しさが変わらない。
- 直し方の案: Lv1 = 2・3・5 の段のぎゃく、Lv2 = すべての段のぎゃく、Lv3 = 九九のぎゃく（あまりあり、1桁の商）のように段階をつける。`DIFFICULTY_INFO` の説明もあわせて直す。

## 4. ウィンドウの大きさで表示がはみ出す → 画面に合わせて縮小する仕組み

- 内容: 画面は FHD（1920×1080）前後を想定したレイアウトで、ウィンドウが小さい・縦が低いと、メニューや結果発表の下の方がはみ出して見えなくなる（`body` が `overflow: hidden` なのでスクロールもできない）。
- やりたいこと: 決まった大きさの「仮の画面」（例: 1280×720 または 1920×1080）に描いて、ウィンドウに収まるように `transform: scale()` で縮小する。
- 実装の案:
  - `src/components/ui/FitStage.tsx` のような部品を作り、`App.tsx` の一番外側を包む。
  - `ResizeObserver`（または `resize` イベント）で `scale = min(画面幅 / 仮の幅, 画面高 / 仮の高さ)` を計算し、中央に置く。拡大はしない（上限 1）か、するかは要相談。
  - 背景（土のテクスチャ）は縮小の外側に置き、画面全体を埋める。
  - マシマシモードの演出 Canvas（`FxCanvas`）は、縮小の内側に置くか外側に置くかで座標の計算が変わる。外側に置いて画面全体に描き、要素の位置は `getBoundingClientRect()`（縮小後の実座標）から取る形にしておくと、縮小を入れても直さずに済む。現状の実装はこの形。
  - 確認: 1920×1080 / 1280×720 / 1024×768 / 768×1024 / 横向きスマホ（844×390）で、はみ出しがないこと。
- 注意: 指示書（`docs/hade-mashimashi-playbook.md` §6.4）にも「低い表示領域では、広い仮の画面に描いて縮める」とある。
- v2（キャラを大きくした版）で 1280×720 は収まることを確認（タイトルの「あそぶ」ボタンの下端 569px）。幅 580px ほどの狭い画面では、ロゴ・レベルボタン・たたかいの場がはみ出す／重なる。
  `BattleField` は自分の大きさ（ResizeObserver）でゾンビの位置を決めているので、縮小の内側に置いても動く（座標は getBoundingClientRect で取っている）。

## 5. ひかえめモードの結果画面で、正解・不正解の枠の色（緑・赤）が出ていない

- 場所: `src/components/ResultScreen.tsx`（`Panel` に `border-green-500 bg-green-900/20` などを付けている所）、`src/index.css` の `.mc-panel` / `.mc-button`
- 原因: `index.css` の `.mc-panel` などは Tailwind v4 の `@layer` の外（レイヤーなし）に書かれている。CSS ではレイヤーなしのスタイルがレイヤー内（Tailwind のユーティリティ）より強いので、
  `mc-panel` に付けた `border-*`・`bg-*`・`p-*` などが効かない。結果画面の枠は全部グレー、背景も同じ黒になっている。
  同じ理由で、メニューやプレイ画面の `Panel` に付けた `py-1`・`bg-black/60` なども効いていない（見た目が少し大きい）。
- 確認: `mc-panel border-green-500 bg-green-900/20` の要素の計算済みスタイルが `border-color: rgb(55,55,55)` / `background: rgba(0,0,0,0.7)` になる（2026-10-18 に確認）。
- 直し方の案（どちらか）:
  - `.mc-*` の定義を `@layer components { ... }` で囲む（Tailwind のユーティリティが勝つようになる）。見た目が変わる所があるので全画面を確認する。
  - 個別に `!border-green-500` のように `!`（important）を付ける。マシマシモードの画面はこの方法で対応済み。
